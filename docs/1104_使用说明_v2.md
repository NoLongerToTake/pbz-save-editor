# v2的6项用法

完整解压后双击“PBZ存档编辑器.exe”。随包包含运行依赖，不用另装Python或Rust。v2独立于v1，原版保留。

## 1. 找到存档与槽位

启动自动寻找本机存档，找不到才提示选择；也可以浏览或填写自定义路径。成功载入的路径会记住。编辑槽位默认是存档记录的当前继续槽位，其他手动档、自动档、周目快照均独立，操作前请核对。

保存正式存档前先退出游戏。程序会检测源文件在编辑期间是否变化，变化后须重新载入，避免覆盖游戏刚写入的进度。

## 2. 背包编辑

“背包”页面保留分类、中文/ID搜索、已有/全部切换、数量/等级编辑、添加和移除。添加未持有物品时切换“全部（可添加）”。普通物品移除为持有量清零并保留历史；装备移除会解除相应装备引用，不能移除最后一把主武器。

书籍、书页和剧情物品只改变持有状态，不自动拼合书籍、完成任务或重放剧情。

## 3. 支线列表与流程

“支线任务”页面可筛选未接取、进行中、已完成、已失败，并按中文名或任务ID搜索。无记录只代表当前槽位没有正式任务记录，前置和是否能够接取尚未核实。

选任务后查看路线、阶段与修改前后的分支状态。完成分支在原生数据里是集合，不天然代表阶段顺序；只对顺序已核实的路线提供“完成到所选阶段”。没有阶段顺序的路线仍可在有成功分支证据时完成到终点。

操作均暂存到内存：

- **完成并补发**：按选定成功路线更新任务记录，再补发预览中勾选的可用奖励。
- **完成到阶段**：完成选中阶段及这条已核实顺序中的此前阶段；后续阶段奖励不发。
- **标记失败**：仅标记任务失败并停止活动目标，不执行失败剧情，不收回已有奖励。
- **重置未接取**：移除该任务记录及对应任务计时，清理直接匹配的任务跟踪；保留奖励。
- **仅补发奖励**：不改变任务记录，只暂存选中的奖励；指定阶段时仅列出该阶段及此前阶段的可用奖励。

**本版只修改任务记录与奖励，NPC、剧情、地图状态暂不适配。** 回退未接取不保证能重新接任务，阶段改写也不保证场景和对话随之改变。

## 4. 奖励预览与领取判断

预览会显示名称/ID、存量、拟补数量、默认选择与判断依据。已持有的唯一装备不会重复添加，也不覆盖其强化等级和历史。

固定且已核实的奖励才可补发。数量型物品和碎屑的历史领取不明时，默认不自动增加；需用户明确勾选并确认补发领取情况不明的项目。随机、阶段关联不明、未核实的ID或周目结算不能猜作确定奖励。

“未查明”不等于没有奖励。阶段奖励、最终奖励、沿途拾取和Boss掉落按来源区分，不因任务完成就全部赠送。当前目录和可用路线、奖励的覆盖情况见docs中的v2验收记录。

外部奖励收据保存在所选备份目录，按文件指纹与槽位识别。收据丢失、换电脑、游戏重新保存或恢复其他文件后，部分领取历史可能无法确认；程序不会把缺失收据直接认作从未领取。收据不写入游戏JSON。

## 5. 撤销、备份和保存

下方待修改清单同时列出任务、物品和货币变化。“撤销上一步”会整体撤销一次任务及其奖励操作；“放弃全部暂存”恢复到载入时的内容。

备份目录可填写或浏览选择，默认在软件文件夹的backups内。

- “立即备份”：备份磁盘原档，不含未保存的暂存修改。
- “预览并保存”：构建和认证通过后，先备份原档再写入。
- “另存为”：备份后输出到自选位置；若覆盖已有另存目标，也先备份该目标。
- “恢复备份”：验证选中的sav/bak，先备份当前文件，再整体恢复。包含全部槽位，可能倒退其他游戏进度。

奖励操作在保存前准备外部收据，写入后收尾；若收尾失败但文件已经保存，程序会报告“已保存”的实际结果，不能因为提示而盲目再补发。

## 6. 验证范围

已对存档副本完成后台读写检查，并按用户后续授权执行了Windows实际窗口测试，没有写入正式游戏存档。

指定支线“不灭侠胆”已验证：S1阶段不发最终奖励，完成S1→1后可补“不灭侠胆”（TU_19006）×1；失败、回退、撤销、自动备份、保存和恢复均已检查。保存后再次预览，该奖励补发数量为0。原生六项任务计数保留，其他任务和槽位未改。

目录包含62项支线，其中51项有成功路线、29项可选择阶段。固定奖励已核实的任务仍有限，未查明的奖励不会猜测补发。目录随程序提供，运行不依赖本机开发草稿；tools中的目录重建脚本仅供维护，需要另备原生资产证据。

首次使用建议另存，用户自行进入游戏检查任务记录、物品和再次保存重载。格式认证通过不等于所有任务修改都能被游戏流程接受。不合适时恢复备份。详细验证范围见“VALIDATION.md”。
